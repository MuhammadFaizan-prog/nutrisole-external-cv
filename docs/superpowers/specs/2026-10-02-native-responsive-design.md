# NutriSole native responsiveness

The user approved the implementation brief in chat on October 2, 2026. All 38 screens must use real native components, preserve the existing artwork and behavior, and adapt to phone width, height, safe areas, keyboard and system text size. Android delivery includes an independently launchable Gradle release APK. iOS source is maintained; Windows cannot verify an iOS binary.

The old native entry passed window dimensions into the shared fixed-coordinate Canvas and extension Viewport. Canvas chose the smaller width/height scale, so short windows compressed all text and touch targets. Text occupied absolute rectangles that could not grow with system fonts. Viewport scaled a 393 × 852 plane, calculated scroll heights from source coordinates, and added a hardcoded 34-unit bottom spacer. This caused unused width, clipped labels, displaced controls and incorrect bottom clearance when the keyboard or Android navigation mode changed. Native-only flowing counterparts now replace those rendering paths; the protected source Canvas/Viewport remain intact for the web reference.

The protected six source modules, their 119-file baseline, and the web runtime remain unchanged. Native counterparts live in `native/responsive/`, reuse the existing stores and action handlers, and replace the native entry renderer only. Six dedicated Flexbox layouts reproduce the supplied PNGs. The 32 extension scenes retain their model's content/actions and convert its card/row/column relationships into flowing native layout; source coordinates identify relationships, never set runtime text rectangles or a whole-screen transform.

One SafeAreaProvider owns system insets. App layout consumes top/left/right/bottom once. Keyboard avoidance applies within that safe viewport; sheets consume their own modal safe area. Headers and footers are siblings of bounded scroll bodies. Text has no fixed height and remains system-scalable. Photos maintain aspect ratio; photographic source overlays remain excluded with the original mask geometry. Camera controls are distinct components over the preview.

Verification covers all routes at 320, 360, 390, 412 and 430 logical widths, varied heights/densities, enlarged text, Android navigation modes and input focus. Native tests, root preservation checks, standalone APK installation, physical emulator taps, screenshots and crash logs are recorded. Runtime verification on a physical phone and iOS requires those devices; do not imply it occurred here.
